# Участие в разработке

Спасибо, что помогаете ОТК. Язык задач, PR и документации — русский; на английском тоже можно. Участники
соблюдают [кодекс поведения](CODE_OF_CONDUCT.md).

## Сообщить об ошибке

Откройте задачу по форме: ошибка, ложное срабатывание (ОТК нашёл ошибку, которой нет), пропуск (ОТК не нашёл
ошибку) или предложение. Чтобы ошибку можно было воспроизвести, приложите:

- вывод `otk doctor` с теми же ключами, что и проверка;
- `summary.json` из каталога прогона (путь печатает `gate`);
- минимальный фрагмент кода 1С, на котором воспроизводится, — без кода и данных заказчика.

Уязвимость — не в открытую задачу, а закрытым сообщением: вкладка Security репозитория → Report a vulnerability
([SECURITY.md](SECURITY.md)).

Метки задачам и PR ставит сопровождающий: `kind/*` — что это (по ним собираются разделы заметок выпуска),
`area/*` — часть ОТК, `needs/*` — чего не хватает для разбора; полный список — `.github/labels.yml`.

## Окружение разработчика

```bash
git clone <репозиторий> && cd otk-1c
PYTHONPATH=src python -m unittest discover -s tests    # Windows: set PYTHONPATH=src
ruff check src tests                                    # стиль: настройки — pyproject.toml
mypy                                                    # типы на границах пакета: [tool.mypy] в pyproject.toml
git config core.hooksPath .githooks                     # ruff, mypy и openspec перед каждым push (как CI)
```

Юнит-тестам платформа 1С не нужна: фикстуры — синтетические мини-выгрузки в самих тестах. Тесты с внешними
программами включаются переменными окружения (`OTK_TEST_BSLLS` и др.), без них — пропуск. Проверки с платформой —
`otk controls` на демо-проекте [otk-1c-demo](https://github.com/cmapnep-tools/otk-1c-demo).

## Как прислать изменение

1. Ветка от `master`: `fix/<кратко>`, `feat/<кратко>`, `docs/<кратко>`.
2. Новое поведение — сначала требования OpenSpec ([docs/development.md](docs/development.md)): изменение в
   `openspec/changes/<изменение>/`, `openspec validate <изменение> --strict`.
3. Исправление ошибки — вместе с тестом, который её воспроизводит (до правки падает).
4. Новый код находки — раздел в [справочнике находок](docs/findings.md); новая проверка —
   [docs/adding-a-check.md](docs/adding-a-check.md).
5. Строка в разделе «Не выпущено» [CHANGELOG.md](CHANGELOG.md). Версию в PR не поднимать — её меняют только PR выпуска и
   следующий за ним PR версии `.dev0` ([docs/development.md](docs/development.md#выпуск)).
6. PR в `master`: зелёный CI, одобрение сопровождающего; история линейная (rebase). Ревью CodeRabbit —
   советы, а не условие слияния.

Присылая PR, вы соглашаетесь, что вклад распространяется по лицензии проекта ([Apache-2.0](LICENSE), раздел 5).
