# Формат EDT

Исходники 1С:EDT (каталог проекта с `src/Configuration/Configuration.mdo`) ОТК понимает наравне с
выгрузкой Конфигуратора: формат распознаётся сам, в `project.source`, `--dir`, `--base-dir`, `--parent` можно
указать и каталог проекта, и его `src`.

- **Статика и BSL LS** читают EDT напрямую (модули, `.mdo`, `Form.form`) — установленная EDT не нужна.
  BSL LS получает проект EDT целиком (метаданные он читает только из `<проект>/src/Configuration/Configuration.mdo`).
- **Пробы в копии ИБ**: формат EDT поддерживается полностью; скорость зависит от того, что изменено.
  - **Изменены только модули** (основная конфигурация, частичная загрузка) — быстро на любом размере, без
    экспорта: модули берутся из EDT, а описание и содержимое формы к модулю формы — частичной выгрузкой копии ИБ
    (`/DumpConfigToFiles -listFile`; форма не менялась, в ИБ она та же). В список загрузки идёт описание формы:
    файл модуля без него платформа загружает с rc = 0, стирая содержимое формы, поэтому если выгрузка не удалась,
    загрузка идёт через экспорт.
  - **Изменены метаданные или формы** (`.mdo`, `Form.form`), новые и удалённые объекты, полная загрузка,
    проект-расширение — через экспорт в выгрузку Конфигуратора (`1cedtcli … -command export`); время растёт с
    размером проекта. Экспорт лежит в каталоге прогона под отпечатком проекта: без изменений повторно не делается.
    Изменён `Form.form` — частичная загрузка; изменён `.mdo` объекта — полная (в `.mdo` лежит и то, что в
    выгрузке — отдельные файлы).

  Ошибки загрузки показываются в путях EDT (модуль, `Form.form`, `.mdo` объекта); файлы, которым в EDT нет
  соответствия (права ролей, макеты, интерфейс), — путём выгрузки с пометкой в тексте ошибки. В журнале сборки
  видно, каким путём шла загрузка: «без экспорта EDT: выгрузка ИБ N c» или «экспорт EDT N c».
- **Расширенная проверка** (общие модули, модули управляемых форм и объектов) заимствует объекты по описаниям
  из экспорта, если сборка его загрузила. Иначе (загружены только модули, копия «без изменений», рабочая база
  без `loadProject`) — одной частичной выгрузкой копии ИБ: владельцы модулей и их формы, общие модули, объекты
  по ссылкам через менеджеры, упомянутые общие реквизиты, корень и язык; время — в журнале и `timings.ibDump`.
  Язык и режим совместимости интерфейса для расширений ОТК читаются из `Configuration.mdo`.
- **Проверка Конфигуратором** (`--designer`, проект-расширение, хуки Platform Tools) показывает ошибки в путях EDT.
  Отрицательный контроль внутри проверки (когда ИБ контроля недоступна) выбирает серверный общий модуль по его
  `.mdo` и после проверки восстанавливает его тем же текстом, что в EDT. `otk pt cf-post` расширенную проверку
  общих модулей проекта EDT не выполняет (пишет примечание): их проверяет `otk gate` в копии ИБ.
- `1cedtcli` ищется так: `--edtcli` / `environment.edtcli` → `OTK_EDTCLI` → самая новая установка
  1C:EDT (`%LOCALAPPDATA%/1C/1cedtstart/installations`) → `PATH`. Тайм-аут экспорта — `environment.edtTimeout`
  (по умолчанию 1800 с). Нет `1cedtcli` — правки одних модулей загружаются и проверяются в ИБ и без него; нужен
  экспорт — в `gate` пробы «не проверено» с причиной, проверка Конфигуратором (`--designer`) не выполняется,
  статика и BSL LS работают; `build` — сбой с подсказкой, `controls` без него не выполняется (нужна загрузка в ИБ).
- Расширение в EDT — как обычно (`parent` — основная конфигурация в любом из двух форматов).
- Время экспорта (EDT 2026.1, тёплый запуск / первый): небольшое расширение — 30 / 80 с; отраслевая конфигурация (2 700 модулей, 25 тыс. файлов выгрузки) — 57 / 165 с; ERP (90 тыс. файлов проекта) — 2 129 с: экспорт идёт в новом рабочем каталоге
  EDT и повторяется при любой правке проекта (тайм-аут по умолчанию 1800 с не хватает). Без экспорта на той же ERP
  (`gate` с правкой пяти модулей, из них два модуля форм): сборка 195 с (выгрузка ИБ 46 с), выгрузка для
  расширенной проверки 27 с, весь `gate` — 7 мин вместо 39.
- Защищённые модули (`.bsl` с двоичным содержимым) в анализ не попадают; форма `BaseForm` адаптированной
  формы расширения — тоже (как и в выгрузке, где её события — в `Form.xml`).
