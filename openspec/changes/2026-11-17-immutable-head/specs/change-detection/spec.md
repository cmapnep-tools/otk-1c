## MODIFIED Requirements

### Requirement: Детерминированный план

ОТК SHALL для одной и той же пары ревизий формировать один и тот же `otk.json`
(порядок модулей, идентификаторы запросов).
ОТК SHALL строить план по указанной Git-редакции и SHALL читать исходники всех последующих шагов из того же неизменяемого снимка по `headSha`. Совпадение `headSha` с текущим `HEAD` SHALL не служить основанием для чтения рабочего дерева. Только явный режим `--worktree` SHALL включать отслеживаемые незакоммиченные изменения в снимок. Ошибка получения снимка SHALL давать инфраструктурный отказ, а не проверку другого источника.

#### Scenario: Повторный сбор

- **WHEN** `otk collect` запускается дважды без изменений
- **THEN** файлы побайтно совпадают

#### Scenario: Грязное дерево при явном HEAD

- **WHEN** после коммита файл BSL изменён без коммита и вызван `gate --head HEAD`
- **THEN** план, статика и строки находок относятся к содержимому коммита; рабочая правка не участвует

#### Scenario: Явная проверка рабочего дерева

- **WHEN** тот же репозиторий проверяют с `--worktree`
- **THEN** план и последующие шаги используют один снимок отслеживаемых изменений рабочего дерева

#### Scenario: HEAD изменился после collect

- **WHEN** между построением плана и статикой текущая ветка перешла на другой коммит
- **THEN** исходники читаются по `headSha` записанного плана, а не по новому HEAD или рабочему дереву

#### Scenario: Тип проекта определяется по проверяемой редакции

- **WHEN** для `gate` или `collect` не задано имя расширения, а файл конфигурации в рабочем дереве отличается от файла в выбранном коммите
- **THEN** ОТК определяет, является ли проект расширением, и его имя по файлу конфигурации из `headSha` плана
- **AND** `gate --worktree` использует снимок отслеживаемого рабочего дерева, `collect --worktree` читает рабочее дерево, а `--dir` читает каталог «стало»
- **AND** явно заданное имя расширения имеет приоритет

#### Scenario: Корень выгрузки определяется по проверяемой редакции

- **WHEN** расположение исходников конфигурации в рабочем дереве отличается от выбранной Git-редакции
- **THEN** ОТК использует `headSha` плана для поиска выгрузки по умолчанию и для распознавания проекта EDT
- **AND** явно указанный каталог выгрузки имеет приоритет над поиском в корне репозитория

#### Scenario: Атрибуты экспорта в Git-редакции

- **WHEN** для запланированного модуля в `.gitattributes` задан `export-ignore` или `export-subst`
- **THEN** снимок по `headSha` содержит этот модуль с точными байтами Git blob, включая неизменённый шаблон `$Format:…$`
- **AND** ОТК пересоздаёт снимок, если для него есть только маркер, созданный механизмом экспорта Git

#### Scenario: Ссылки на каталоги в Git-редакции

- **WHEN** Git-редакция содержит ссылку или цепочку ссылок на каталог того же Git-коммита, в том числе в другом источнике
- **THEN** ОТК создаёт ссылки с типом каталога, даже если его путь следует после них в порядке Git или другой источник извлекается позже
- **AND** на Windows цель ссылки может отличаться регистром букв от имени каталога или следующей ссылки в Git
- **AND** цикл ссылок приводит к ошибке извлечения без маркера готовности

#### Scenario: Каталог сценариев задан Git-ссылкой

- **WHEN** путь каталога сценариев содержит Git-ссылку или цепочку ссылок на каталог того же коммита
- **THEN** ОТК извлекает каталог-цель из выбранной Git-редакции и записывает в план пути к сценариям относительно корня извлечённого дерева
- **AND** отсутствующий каталог или ссылка на отсутствующую цель дают пустой список сценариев
- **AND** ссылка за пределы дерева редакции приводит к ошибке извлечения без маркера готовности

#### Scenario: Несовместимые с Windows пути Git

- **WHEN** Git-редакция содержит два файла или каталога, чьи пути на Windows совпадают без учёта регистра
- **THEN** извлечение на Windows завершается ошибкой без маркера готовности, а не проверкой одного из этих файлов
- **AND** готовые снимки, созданные до этой проверки, извлекаются заново

#### Scenario: Указатели Git LFS в редакции

- **WHEN** в выбранной Git-редакции вместо файла сохранён указатель Git LFS
- **THEN** снимок содержит исходные байты указателя без гидратации
- **AND** если указатель входит в выгрузку для загрузки в 1С, ОТК прерывает загрузку с диагностикой Git LFS
