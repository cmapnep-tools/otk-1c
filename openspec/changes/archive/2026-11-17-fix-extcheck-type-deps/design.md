# Design

## Что требует платформа

Проверено на 8.3.23.2236 в синтетической конфигурации (`ibcmd infobase config import --extension=otk_check`):

| Расширение содержит | Загрузка |
| --- | --- |
| `Catalog.Items` с реквизитом `Тип: CatalogRef.Items` | ошибка `Неизвестное имя типа - CatalogRef.Items` |
| `Catalog.Items` заимствован (без реквизитов) | загружается, `rc=0` |
| `DefinedType.Основание` без `<Type>` и без `CatalogRef.Items` | ошибка `Неизвестное имя типа - CatalogRef.Items` |
| `DefinedType.Основание` оболочкой + его состав заимствован | загружается, `/CheckModules` — «Синтаксических ошибок не обнаружено» |

Тип в `<v8:Type>` не разрешается «сам собой»: платформа ищет объект среди заимствованных. Убирать `cfg:` из типа
бесполезно — текст ошибки тот же. Определяемый тип платформа наполняет из основной конфигурации, но только если
объекты состава в расширении разрешаются: `<Type>` в оболочке не обязателен, а состав заимствовать нужно.

## Почему оболочка

Полное копирование реквизитов у зависимостей дало бы транзитивное замыкание по реквизитам: на отраслевой
конфигурации (10 310 объектов) замыкание от 400 корней — медиана 2 700 объектов, максимум 2 797 на расширение,
1,2 с только на сбор описаний. Конфигуратор такое расширение грузит минутами, и это на каждый прогон.

Оболочка (только сам объект, `ObjectBelonging=Adopted`, `ExtendedConfigurationObject`) сама тянет лишь свои
свойства-типы — их в описании немного (`DefinedType`, `Characteristic`), поэтому замыкание короткое и
завершается. Для компиляции оболочки достаточно: `Товар.Артикул` и
`Справочники.Items.ПустаяСсылка().Артикул` в расширении компилируются. Цена: опечатку в поле такого объекта
оболочка не ловит — её ловит объект, заимствованный полным (по ссылке через менеджер или как владелец модуля).

Конфигуратор сам заимствует так же: в выгрузке расширения, сделанной им, у заимствованного объекта есть только
сам объект (`ObjectBelonging=Adopted`) без реквизитов, а все `cfg:`-ссылки указывают на заимствованные объекты.

## Таблица типов

`ib_tools.TYPE_COLLECTIONS` — из `index.COLLECTIONS` (вид → каталог выгрузки) с суффиксами
`Ref`, `Object`, `Manager`, `Selection`, `List`, `RecordSet`, `RecordManager`, `RecordKey`, `ValueManager`,
`Builder` плюс `Constant`, `DefinedType`, `Characteristic` (план видов характеристик),
`BusinessProcessRoutePointRef`. Не объекты — `xs:`, `v8:`, `DynamicList`, `AnyIBRef` — пропускаются.

## Две фазы замыкания

`adopted_object(..., fields=False)` возвращает `"types"` — объекты, нужные вслед за описанием:

- полный объект (`fields=True`) — типы скопированных реквизитов, измерений, ресурсов и ТЧ (у EDT — всех
  элементов описания); формы и значения перечисления тоже копируются только в этом режиме;
- оболочка — только типы свойств самого объекта (Designer: до `<ChildObjects`; EDT: прямой `<type>` корня).

`objects_for` обходит `types` рабочим списком, `ib_names` — двумя фазами: сначала полные объекты, затем
оболочки. Ключ повтора и цикла — `(коллекция, имя.lower())`: имена в типах и в файлах различаются регистром,
и `layout.find_ci` ищет файл без учёта регистра.

`edt.KINDS` получил `DefinedTypes → DefinedType`: без этой строки строка `-listFile` для определяемого типа не
строилась, и оболочка зависимостей в EDT-режиме терялась бы молча.
