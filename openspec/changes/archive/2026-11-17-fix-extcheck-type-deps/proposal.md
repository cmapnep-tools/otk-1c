# Заимствование объектов по типам реквизитов в extcheck

## Why

Временное расширение extcheck заимствовало объекты, на которые модули ссылаются через менеджеры
(`Справочники.X`), но не объекты, на которые ссылаются **типы** их реквизитов, измерений, ресурсов и табличных
частей. Реквизит заимствованного объекта приходит вместе с `<v8:Type>cfg:CatalogRef.Items</v8:Type>`, и если
`Справочник.Items` в расширении нет, платформа не загружает расширение целиком:

```
[ERROR] Неизвестное имя типа - CatalogRef.Items
```

Проверка при этом не выполняется: в режиме `auto` это «не проверено» с `check: extcheck`, а в `on` — сбой.
Тот же эффект даёт определяемый тип: `<v8:TypeSet>cfg:DefinedType.Ссылка</v8:TypeSet>` без заимствованного
`DefinedType.Ссылка` (а оболочке определяемого типа нужен ещё и объект из его состава). Внешнее замечание
LOCAL-2381 к 1.1.1: полный сбор зависимостей заимствуемых объектов, транзитивное замыкание с защитой от циклов.

## What Changes

- Сбор зависимостей по типам: значения `<v8:Type>` и `<v8:TypeSet>` описания объекта (`layout.type_values`)
  переводятся в объекты по таблице «префикс типа → коллекция выгрузки» (`ib_tools.type_references`), включая
  составные типы, определяемые типы, план видов характеристик и точку маршрута бизнес-процесса.
- Замыкание: зависимости по типам заимствуются в то же расширение, транзитивно, до замыкания; повтор и цикл
  снимаются ключом `(коллекция, имя в нижнем регистре)`.
- Зависимость по типу заимствуется **оболочкой** — только сам объект, без реквизитов, табличных частей, значений
  перечисления и свойств (общие реквизиты): расширению нужен сам тип. Оболочка, у которой есть свои
  свойства-типы (определяемый тип, тип значений характеристик), заимствует свои зависимости — цепочка на ней
  не обрывается, но и не разрастается: реквизиты она не копирует. Объекты, заимствованные ради модулей и ссылок
  по менеджерам, по-прежнему приходят с реквизитами — на них опечатка в поле ловится.
- Частичная выгрузка ИБ для исходников EDT (`extended_check.ib_names`) собирает тот же список: те же объекты по
  типам, теми же двумя фазами (полный объект — все его типы, оболочка — только свой тип), с той же защитой от
  циклов; `DefinedType.X` в `-listFile` выгрузки принимается платформой (проверено на 8.3.23).
- Типы реквизитов из описания не удаляются и не подменяются ради обхода ошибки загрузки.

## Capabilities

### Added Capabilities

- `static-checks`: расширенная проверка — заимствование зависимостей по типам реквизитов и транзитивное замыкание.
