# Маркер готовности дерева редакции

## Why

Готовность извлечённой редакции git (`trees/<sha>`) отмечается файлом-маркером `<дерево>-<хеш src>.done`,
и `_covered` решал о готовности по одному содержимому маркера — пути источника. Пустой маркер даёт пустой
список сегментов, а он префикс любого источника: такой файл «покрывает» дерево целиком, и `materialize`
отдаёт неполное дерево без повторного извлечения. Чужой файл с подходящим именем выдаёт себя за маркер
другого источника. Сам ОТК таких маркеров не пишет (запись атомарная), это порча извне: сбой диска, ручная
правка, совпавшее имя.

## What Changes

- Маркер принимается, только если его имя посчитано от его собственного содержимого и содержимое непустое;
  иначе маркер — как отсутствующий: дерево извлекается заново (и маркер снимается, как нечитаемый).
- Одна проверка закрывает пустые, испорченные и чужие маркеры; неполное дерево больше не считается готовым.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `change-detection`: добавлено требование о готовности дерева редакции — источник считается извлечённым
  только по маркеру, чьё имя и содержимое согласованы.

## Impact

`src/otk_1c/sources/workspace.py` (`_covered`), тесты `tests/test_gate_sources.py`. Кэш деревьев редакций
перестаёт принимать испорченные маркеры: после обновления неполное дерево с таким маркером извлечётся заново.
