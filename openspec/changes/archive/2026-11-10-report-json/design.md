# Дизайн

## Контекст

`gate` и `doctor` уже используют `_json_out`, который отделяет журнал в stderr и гарантирует один JSON-объект в stdout. Остальные команды либо печатают текст, либо не имеют типизированной схемы. Сборка ИБ, hooks, scaffold и построение индексов меняют внешнее состояние.

## Решения

- Для JSON использовать схему `otk.<command>-result.v1`, сохранять код выхода команды и отправлять журнал в stderr.
- `console bases --json` возвращает только имена баз и состояние подключения; соединения, пути файла баз и учётные данные не входят в результат.
- Каждый `--dry-run` формирует план без вызова операции записи, блокировки ИБ, создания каталога или запуска внешней команды черновика.
- Проверка возможности создать ИБ общая для реального build и preview; пересечение `--artifacts` с runDir блокируется до любой очистки.
- `--assume-current` для Git- и каталожных планов только сохраняет состояние и не загружает выгрузку.
- Повтор `gate` после прерывания всегда заново выполняет collect и удаляет файлы шагов прошлого плана; готовые шаги не переиспользуются.
- Публичная сводка проходит через allowlist полей. Строки соединения и значения паролей маскируются; строка кода допускается только как контекст конкретной находки.
- Все текстовые форматтеры применяют ту же публичную проекцию, включая CI-логи и stderr `report --json`; значения при ключах в кавычках (JSON-фрагменты) тоже маскируются.
- CI публикует только сводки, JUnit, Problems и SARIF; планы, сырые шаги и журналы исключены.
- Поведение команд без новых флагов сохраняется.

## Риски

- Встроенная сводка дублирует данные `summary.json`, увеличивая JSON-ответ. Это намеренно: ответ команды самодостаточен для агента.
- Повторный запуск `gate` тратит время на повторные проверки, но не рискует смешать результат нового плана с файлами предыдущего.
