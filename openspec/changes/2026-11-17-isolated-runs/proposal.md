# Изоляция параллельных прогонов gate

## Проблема

Сейчас каждый `gate` одного рабочего дерева пишет `otk.json` и файлы шагов в один каталог `workspace.run_dir`. Одновременные запуски удаляют и перезаписывают файлы друг друга; `report.from_files` может собрать сводку из чужих шагов. Кроме того, пробы двух запусков могут обращаться к одной копии ИБ.

## Решение

Выделять каждому запуску `gate` отдельный каталог атомарно. Публичный путь в ответе `gate --json` и консоли должен вести именно к нему. `report` принимает конкретный каталог, а без него выбирает последний завершённый запуск проекта. Доступ к общей копии ИБ на время проб и проверки Конфигуратором должен быть взаимно исключён между процессами; при занятой ИБ прогон завершается диагностикой `ib-busy` без смешения артефактов.

## Границы

Изменяются только организация файлов `gate`, поиск его отчёта и координация общей ИБ. Форматы публичных JSON-отчётов и коды вердикта сохраняются. Каталоги старых прогонов остаются доступными до явной очистки пользователем. `collect`, `static`, `build` и `designer-check` сохраняют собственные рабочие каталоги; отдельная координация этих команд может потребовать дальнейшей задачи.

## Риски

Каталоги прогонов будут накапливаться. Дополнительный короткий компонент пути не должен превышать ограничения Windows для глубокой выгрузки 1С. Поиск последнего отчёта должен игнорировать незавершённые прогоны. Блокировка ИБ должна освобождаться после ошибки или остановки процесса.
