# Design

## Режим обычного клиента

Режимы `/CheckModules` для расширенной проверки зависят от проверяемых модулей: если хотя бы у одного из них в
плане есть контекст `OrdinaryClient` (флаг `ClientOrdinaryApplication` при работе в обычном приложении, модуль
приложения, модуль объекта такой конфигурации), к базовым режимам добавляется `-ThickClientOrdinaryApplication`.
Проверяются все модули расширения сразу, поэтому режим общий для прогона.

Контексты, которые проверка закрывает, вычисляются по тому же признаку и складываются в `RunContext.ext_contexts`.
`runner` снимает «не покрыто» по ним, а не по статическому списку: модуль без пробы (`*`) считается покрытым,
только если все его контексты входят в проверенные.

## Обязательное покрытие

`environment.requiredContexts` — список контекстов, покрытие которых обязательно. `collect` записывает его в
план (`requiredContexts`), чтобы `report` по файлам прогона давал тот же вердикт.

`report.build` считает непокрытые обязательные контексты по `uncovered` и `notChecked` после снятия того, что
закрыла полная проверка Конфигуратором (`designer_closes`). Если такие есть — вердикт «не покрыто обязательное:
…» и код 2; сами записи остаются в «не покрыто этим прогоном» и «не проверено», чтобы было видно, чем закрыть.

Код 2 выбран, потому что это не находка в коде: прогон не состоялся в обещанном объёме, и правка кода его не
изменит — как при «ничего не проверено». `gate --json` отдаёт `status: not-checked` с вердиктом в поле `verdict`.

## Временное расширение в обычном приложении

Приёмка на платформе 8.3.23 нашла в том же пути вторую ошибку: `ib_tools.generate_test_extension` писал в
`Configuration.xml` расширения `<DefaultRunMode>ManagedApplication</DefaultRunMode>` константой. Основной режим
запуска — контролируемое свойство заимствованной конфигурации, поэтому в конфигурацию обычного приложения
расширение не загружалось: «Значение контролируемого свойства ОсновнойРежимЗапуска у объекта … не совпадает со
значением в расширяемой конфигурации», и расширенная проверка давала сбой инфраструктуры (код 2) — то есть
режим обычного клиента был недостижим без этой правки.

`ib_tools.base_properties` теперь возвращает ещё и `runMode` (`DefaultRunMode` выгрузки; свойства нет — обычный
`ManagedApplication`, как раньше), а генератор расширения берёт его оттуда. Режим запуска нужен всем генераторам
расширений ОТК (`extcheck`, `designer_check`, `availability`, `scaffold`, YAxUnit), поэтому правка в общем
`ib_tools`, а не в `extcheck`.

## Приёмка

Стенд — синтетическая выгрузка обычного приложения (8.3.23, режим совместимости `Version8_3_23`): общий модуль с
флагами `Server`, `ExternalConnection`, `ClientOrdinaryApplication`, в «стало» добавлен экспортный метод.
Копия ИБ собрана из выгрузки «было», `environment.requiredContexts = ["OrdinaryClient"]`.

- `gate --dir head --base-dir base` — код 0: `OrdinaryClient` в «не покрыто» не остаётся, `extcheck` выполняет
  режим `-ThickClientOrdinaryApplication` (в выводе проверки режим «Толстый клиент (обычное приложение)»).
- Тот же прогон с ошибкой компиляции в модуле — код 1, находка `extcheck` с этим режимом в списке.
- `--set checks.extcheck=off` — код 2, вердикт «не покрыто обязательное: OrdinaryClient»; `--json` —
  `status: not-checked`.
