# scenario-tests Specification

## Purpose
Сценарные тесты на логику: подключаемые тесты YAxUnit, выбор по изменённым методам, заготовки тестов,
изоляция данных.

## Requirements

### Requirement: Подключаемые сценарии

ОТК SHALL поддерживать сценарные тесты на логику в формате основного раннера (модули
тестового расширения YAxUnit), лежащие в репозитории проекта в `tests/cfe/<имя>` (раскладка VS Code
«1C: Platform Tools»: те же тесты запускаются из панели тестов редактора); каталог задаётся настройкой
`[scenarios] path`. Временные пробы ОТК в эту раскладку не попадают. Тесты пишет пользователь;
ОТК их выбирает и запускает.

#### Scenario: Сценариев нет

- **WHEN** в проекте нет ни одного сценария
- **THEN** шаг выполняется с результатом «0 сценариев», без ошибок

#### Scenario: Движок YAxUnit в каталоге тестов

- **WHEN** в `tests/cfe` лежат исходники движка YAxUnit (команда Platform Tools «Добавить YAxUnit»), в том
  числе не добавленные в git
- **THEN** движок и расширения без тестов не считаются тестовыми расширениями: не загружаются в копию ИБ и не
  ломают прогон

### Requirement: Выбор сценариев по изменениям

ОТК SHALL выбирать сценарии, связанные с изменёнными методами (по явной привязке в
`otk.toml` или по тегу теста с полным именем метода), и запускать только их.

#### Scenario: Изменён метод с привязанным тестом

- **WHEN** изменён `ПродажиСервер.СуммаПродаж`, а тест помечен тегом `ПродажиСервер.СуммаПродаж`
- **THEN** этот тест есть в `scenarios` плана и выполняется

#### Scenario: Полный прогон

- **WHEN** задан ключ `--all-scenarios`
- **THEN** выполняются все сценарии проекта

### Requirement: Заготовки тестов для изменённых методов

ОТК SHALL по команде `otk scaffold` добавлять изменённым методам без теста с их тегом каркас теста
YAxUnit в тестовое расширение проекта (нет расширения — создавать). Каркас помечен пропущенным, пока тест не
написан; существующие процедуры не перезаписываются. Черновик теста — только через внешнюю команду
`[scaffold] draft` (протокол: JSON о методе на stdin, тело теста на stdout); без неё — пустой каркас.

#### Scenario: Метод без теста

- **WHEN** изменён экспортный метод `М.Разобрать`, а теста с тегом `М.Разобрать` нет
- **THEN** в тестовом модуле появляется `ЮТТесты.ДобавитьТест(…, "М.Разобрать")` и процедура с подсказкой
  вызова и `ЮТест.Пропустить`; в сводке gate тест попадает в «не проверено», а не в «пройдено»

#### Scenario: Метод уже покрыт

- **WHEN** у изменённого метода есть тест с его тегом
- **THEN** заготовка не создаётся

### Requirement: Изоляция данных

Сценарии SHALL выполняться так, чтобы не оставлять данных в базе (транзакция с откатом или
средства тестовых данных раннера), и база должна оставаться пригодной для следующего прогона.

#### Scenario: Проведение документа в тесте

- **WHEN** сценарий проводит документ
- **THEN** после прогона документа и движений в базе нет
