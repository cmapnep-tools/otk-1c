# ib-console Specification

## Purpose
Консоль копии ИБ для человека и ИИ-агента (командная строка и MCP): запросы и разбор без выполнения,
метаданные, журнал регистрации; только чтение.

## Requirements

### Requirement: Запрос к копии ИБ

Консоль SHALL выполнять запрос или пакет запросов в базе по псевдониму и возвращать для каждого
результата колонки, строки (не больше лимита), общее число строк и признак усечения.

#### Scenario: Ссылки в результате

- **WHEN** в результате есть ссылка
- **THEN** она возвращается как представление, XML-тип и УИД; тип и УИД принимаются обратно параметром

#### Scenario: Даты

- **WHEN** параметр — дата `{"date": "2026-01-31T23:59:59"}`
- **THEN** в запрос попадает та же дата без сдвига на часовой пояс, в ответе — та же строка

#### Scenario: Ошибка запроса

- **WHEN** в запросе нет поля
- **THEN** ответ — ошибка с номером строки, колонки и текстом платформы; сервер продолжает работать

### Requirement: Разбор запроса без выполнения

Консоль SHALL разбирать текст запроса платформой без выполнения и сообщать ошибку с позицией или список
параметров.

#### Scenario: Ошибка в тексте

- **WHEN** в тексте запроса синтаксическая ошибка или нет поля
- **THEN** ответ — признак ошибки, номер строки, колонки и текст платформы; запрос не выполняется

#### Scenario: Параметры

- **WHEN** текст запроса без ошибок
- **THEN** ответ — признак успеха и имена параметров запроса

### Requirement: Метаданные живой базы

Консоль SHALL отдавать список объектов коллекции и состав объекта (стандартные реквизиты, реквизиты,
табличные части, измерения, ресурсы, графы, значения перечисления) с типами.

#### Scenario: Коллекция

- **WHEN** запрошена коллекция (`Справочники`, `РегистрыСведений`, ...)
- **THEN** ответ — имена объектов, с синонимом, если он отличается от имени

#### Scenario: Объект

- **WHEN** запрошен объект по полному имени
- **THEN** ответ — его поля с типами по группам (стандартные реквизиты, измерения, ресурсы, реквизиты, графы), табличные части с реквизитами и значения перечисления; пустые группы не выводятся

#### Scenario: Нет объекта

- **WHEN** объекта с таким полным именем нет
- **THEN** ответ — ошибка «объект метаданных не найден»; сервер продолжает работать

### Requirement: Журнал регистрации

Консоль SHALL выгружать журнал регистрации базы с отбором (период, уровень, пользователь, событие, метаданные, данные,
сеанс, приложение, компьютер, статус транзакции) — записи или подсчёт по выбранным полям.

#### Scenario: История объекта

- **WHEN** в отборе ссылка `{type, id}`, полученная из ответа запроса
- **THEN** возвращаются все записи журнала по этому объекту (добавление, изменения, проведение)

#### Scenario: Неверный отбор

- **WHEN** в отборе неизвестное поле или несуществующий объект метаданных
- **THEN** ошибка с понятным текстом, без обращения к журналу

### Requirement: Соединение не мешает работе с базой

Сервер MCP SHALL держать соединение между вызовами и отпускать его по простою (по умолчанию 120 с) и по
`ib_disconnect`.

#### Scenario: Простой

- **WHEN** вызовов не было дольше порога простоя
- **THEN** сеанс 1С закрыт и файлы блокировки базы не удерживаются

### Requirement: Только чтение и секреты

Консоль SHALL NOT изменять данные и SHALL NOT хранить пароли открытым текстом: пароль берётся из
Диспетчера учётных данных Windows (`password_cred`) или переменной окружения (`password_env`).

#### Scenario: Пароль из хранилища

- **WHEN** у базы задан `password_cred` или `password_env`
- **THEN** пароль читается при соединении и не попадает в файл баз и в ответы консоли (`ib_bases` отдаёт соединение, пользователя и состояние)

#### Scenario: Нет учётной записи

- **WHEN** учётной записи `password_cred` нет в Диспетчере учётных данных
- **THEN** ответ — ошибка с её именем, соединение не открывается

#### Scenario: Нет операций записи

- **WHEN** агент работает с базой через консоль
- **THEN** ему доступны только запрос, разбор запроса, метаданные и журнал регистрации; выполнения кода и записи данных нет
