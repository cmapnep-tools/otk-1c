# test-runner Specification

## Purpose
Исполнение проверок в 1С за единым адаптером раннера: список тестов из плана, запуск по контекстам, пакетный
режим, падение при старте сеанса, варианты исполнения (COM, YAxUnit).

## Requirements

### Requirement: Единый адаптер раннера

ОТК SHALL запускать пробы, разбор запросов и сценарии через интерфейс адаптера
(`prepare`, `run(plan) -> results`, `parse_report`) с реализацией для YAxUnit (основная) и
Vanessa-ADD (запасная).

#### Scenario: Выбор раннера

- **WHEN** в настройке проекта `runner: add`
- **THEN** используется адаптер Vanessa-ADD, а формат `otk.json` и отчёта не меняется

### Requirement: Список тестов из плана без пересборки

Раннер SHALL строить список тестов из `otk.json` во время запуска (YAxUnit —
`ИсполняемыеСценарии` + `СПараметрами`, ADD — `ЗаполнитьНаборТестов` + `ПараметрыТеста`), без
пересборки тестового расширения или обработки.

#### Scenario: Новая задача

- **WHEN** меняется только `otk.json`
- **THEN** тестовое расширение не перезагружается, а имена тестов в отчёте отражают модуль и контекст (`Проба[Сервер] ОбщийМодуль.X`)

### Requirement: Запуск по контекстам

Раннер SHALL запускать клиентский сеанс каждого нужного режима (тонкий клиент; толстый клиент
обычного приложения — если в плане есть OrdinaryClient) только при наличии тестов для него.

#### Scenario: Только серверные модули

- **WHEN** в плане нет клиентских контекстов
- **THEN** запускается один сеанс, серверные тесты исполняются через него

### Requirement: Падение при старте сеанса

Раннер SHALL запускать клиент с `/Out` и следить за журналом регистрации ИБ, чтобы распознавать
ошибки компиляции, которые не дают сеансу дойти до тестов: событие `_$PerformError$_` (модули,
вызываемые при старте, глобальные модули) или выход клиента с ненулевым кодом и текстом в `/Out`
(модуль сеанса). Такая ошибка — `compile-error` с модулем и позицией, а не сбой инфраструктуры.

#### Scenario: Ошибка в модуле сеанса

- **WHEN** клиент завершился с кодом 1, а `/Out` содержит `{МодульСеанса(208,2)}: …`
- **THEN** находка `compile-error` по модулю сеанса со строкой 208

#### Scenario: Ошибка обработана YAxUnit

- **WHEN** в журнале появилось `_$PerformError$_`, но клиент сам завершился и записал отчёт
- **THEN** исход берётся из отчёта, клиент не закрывается принудительно

### Requirement: Пакетный режим

Раннер SHALL работать без интерактивных окон, с ограничением времени на сеанс, и при зависании
завершать процесс и возвращать код 2.

#### Scenario: Модальное окно в базе

- **WHEN** при старте сеанса появляется модальное окно и тесты не стартуют за отведённое время
- **THEN** процесс 1С завершается, а вердикт — «сбой инфраструктуры» с последним логом

### Requirement: Варианты исполнения проверок

ОТК SHALL исполнять каждую проверку через сменный исполнитель (COM, YAxUnit, Vanessa-ADD,
Конфигуратор) с выбором в `otk.toml`; по умолчанию SHALL выбираться самый быстрый доступный
вариант, а при его недоступности — следующий, с отметкой в сводке.

#### Scenario: COM недоступен

- **WHEN** COM-коннектор нужной версии не зарегистрирован
- **THEN** серверные пробы и разбор запросов выполняются через YAxUnit, а сводка отмечает «COM недоступен — использован YAxUnit»

#### Scenario: Модуль с ветками НЕ ВнешнееСоединение

- **WHEN** изменённый серверный модуль содержит `#Если НЕ ВнешнееСоединение`
- **THEN** модуль пробуется и через COM, и на сервере через YAxUnit
