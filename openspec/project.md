# ОТК — проверка изменений кода 1С

## Назначение

ОТК проверяет только изменённый код конфигурации или расширения 1С и отвечает: «можно отправлять» или «нельзя,
вот почему». Главное — то, чего компиляция модулей Конфигуратором не видит: запросы, имена в строках, обработчики,
методы платформы новее режима совместимости, открытие форм, логика изменённых методов; кроме того — быстрая
проверка компиляции изменённого вместо расширенной проверки всей конфигурации (`/CheckModules …
-ExtendedModulesCheck`), время которой не зависит от объёма правки.

Проверка всех модулей Конфигуратором не отменяется: она остаётся в CI страховкой, а ОТК сверяется с ней каталогом
контрольных дефектов (`control-defects`).

## Принцип

ОТК не исполняет весь код: он сочетает статические шаги без базы и короткие пробы в копии ИБ.

1. **Статика без базы** (`static-checks`): анализаторы BSL до и после правки, ссылки изменённых строк по индексу
   метаданных, зависимые модули, обработчики из XML, методы и типы платформы по справке.
2. **Пробы в базе** (`compile-probes`): одна проба на модуль и контекст компиляции. 1С компилирует модуль целиком
   при первом обращении в контексте, поэтому одна проба ловит синтаксис во всём модуле.
3. **Разбор запросов** (`query-check`): тексты запросов изменённых методов разбирает платформа без выполнения.
4. **Формы и сценарии** (`form-smoke`, `scenario-tests`): открытие изменённых форм, тесты YAxUnit по изменённым
   методам.

Шаги общаются только файлами по JSON Schema (`otk.json`, `static.json`, `run.json`), а не вызовами Python
(`architecture`): любой шаг можно переписать на другом языке или запустить отдельно.

## Технологии

| Слой | Технология |
| --- | --- |
| Оркестратор, статика | Python 3.11+, без обязательных внешних зависимостей (`pywin32` — для COM на Windows) |
| Анализаторы BSL | BSL Language Server, bsl-analyzer — за общим адаптером |
| Раннер тестов в 1С | YAxUnit, за общим интерфейсом исполнителей (`test-runner`) |
| Сборка копии ИБ | пакетный Конфигуратор (частичная загрузка), `ibcmd` (полная), `1cedtcli` (экспорт EDT) |
| CI | шаблоны Forgejo Actions; раннер с платформой 1С для проб |
| Платформы | 8.3.2x и 8.5 |

## Соглашения

- Исходники — выгрузка Конфигуратора (XML + BSL) или проект 1C:EDT (`edt-format`).
- Тексты, сообщения, сводка — на русском; идентификаторы Python — английские. Встроенный язык — русский и
  английский варианты: всё, что зависит от языка (ключевые слова, коллекции метаданных, `ВЫБРАТЬ`/`SELECT`, имена
  методов платформы), берётся из словаря языка; вариант определяется по `ScriptVariant` в `Configuration.xml`.
- Артефакты прогона (`otk.json`, сводки, журналы, временные ИБ) — вне дерева исходников, в каталоге прогона.
- ОТК меняет только свою копию ИБ или явно заданную рабочую базу (с возвратом к прежнему виду).
- Шаг, который ничего не проверил (0 проб, 0 запросов), явно пишет это в сводку и не засчитывается «зелёным»;
  недоступная проверка — «не проверено» с причиной.
- Утверждение о поведении платформы, не подтверждённое на ней, — гипотеза, пока его не закрыл контрольный дефект.

## Ограничения платформы

- Конфигуратор из командной строки проверяет только всю конфигурацию или всё расширение: ключа «один модуль» нет.
- `/CheckModules` без ключей режимов ничего не проверяет — ключи режимов задаются всегда, доверие только после
  отрицательного контроля.
- `ibcmd` для файловой ИБ: режим `infobase config …`, свой `--data=<каталог>`, stdin закрыт.
- Контекст «внешнее соединение» требует зарегистрированного COM-соединителя нужной версии платформы.
- Linux (входит в 1.0): тот же `gate` с платформой; окнам 1С нужен X-сервер — ОТК поднимает свой Xvfb; COM нет —
  серверные пробы и запросы через YAxUnit, внешнее соединение «не проверено».

## Развитие

Не входит в 1.0, но архитектура не должна этому мешать:

1. **Оркестратор на OneScript** — для окружений без Python; поэтому шаги общаются файлами.
2. **Пробы в веб-клиенте** — сейчас веб-клиент проверяется статикой и расширенной проверкой Конфигуратора в режиме
   `-WebClient`.
