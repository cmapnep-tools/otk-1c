## [1.0.0] - 2026-11-04

Первый публичный выпуск.

### Добавлено

- `otk gate`: проверка только изменённого по git или по двум каталогам выгрузки; разовая проверка доработок
  относительно конфигурации поставщика ИБ (`--vendor`).
- Статика без базы: ссылки на метаданные, экспортные методы и число параметров, имена форм, обработчики,
  методы и типы платформы по справке и их доступность по контексту; анализаторы BSL (BSL LS, bsl-analyzer) —
  только новые замечания.
- Пробы в копии ИБ: компиляция изменённых модулей по контекстам (сервер, внешнее соединение, тонкий клиент),
  разбор запросов платформой, включая собранные в коде, расширенная проверка изменённых модулей Конфигуратором,
  дымовой тест форм, сценарные тесты YAxUnit по изменённым методам и их заготовки.
- Выгрузка Конфигуратора и проект 1C:EDT, конфигурации и расширения, русский и английский встроенный язык;
  правки одних модулей проекта EDT проверяются в копии ИБ без экспорта проекта (описания — частичной выгрузкой
  ИБ), в том числе без установленной 1C:EDT; проверка Конфигуратором (`--designer`, проект-расширение, хуки
  Platform Tools) показывает ошибки в путях EDT.
- Сводка Markdown/HTML, JUnit, SARIF, Problems VS Code; коды выхода 0/1/2.
- Хук pre-push, хуки VS Code «1C: Platform Tools», проверка в рабочей базе с возвратом; шаблоны CI — Forgejo и Gitea
  Actions, GitHub Actions, GitLab CI, Jenkins: один шаг `otk ci`, база — целевая ветка запроса из переменных CI,
  артефакты — каталогом `--artifacts`; страница «Что ОТК заменяет в вашем CI»; проверка всех модулей
  Конфигуратором с базовой линией и отрицательным контролем.
- Контрольные дефекты (`otk controls`) и таблицы сравнения с Конфигуратором и анализаторами BSL.
- Консоль копии ИБ и MCP-сервер (запросы, метаданные, журнал регистрации — только чтение), анализ
  технологического журнала.
- Платформа находится и в установке «для пользователя» (`%LOCALAPPDATA%\Programs\1cv8_x64`, `1cv8_x86`) — для
  запуска, хуков Platform Tools и справки синтакс-помощника.
- Основная конфигурация, не применённая к БД (`--vendor`, рабочая база без загрузки), не проверяется прежним
  кодом: копию ИБ ОТК обновляет (`/UpdateDBCfg`), в рабочей базе пробы исполнения — «не проверено» с причиной.
- Итоги пилота на реальных задачах и дозамера (EDT без экспорта, `--vendor`, bsl-analyzer) — `docs/pilot.md`.
- Реестр сторонних инструментов и заимствований: лицензии, проверенные версии, правило переноса кода —
  `docs/third-party.md`; раздел «Благодарности» в README.
- Сценарий для ИИ-агентов: проверка после каждой правки, что читать в выводе и `summary.json`, правило для
  инструкций агента — `docs/agents.md`.
- Статика на Linux без платформы проверена (WSL2, Ubuntu 24.04): тот же результат, что на Windows. BSL LS
  получает справку платформы, известную ОТК (без неё молчат правила по событиям); замечания BSL LS на Linux
  больше не теряются; имена объектов из кода ищутся в выгрузке без учёта регистра.
- Пробы с платформой на Linux (WSL2, Ubuntu 24.04, 8.3.27): `gate` и `controls --parity` — те же находки, что на
  Windows, кроме внешнего соединения (COM нет — «не проверено», серверный код и запросы — через YAxUnit). Окна 1С —
  на своём Xvfb ОТК (`doctor`: `display`), потомки клиента завершаются группой процессов, занятая база — по ответу
  Конфигуратора. Установка платформы и лицензия для разработчиков на Linux — `docs/linux.md`.
- CI проекта на GitHub Actions: ruff и формат спецификации, юнит-тесты на Windows и Linux (Python 3.11 и 3.14),
  сборка пакета с проверкой установки колеса. Лицензия в метаданных пакета — выражение SPDX (`Apache-2.0`),
  LICENSE и NOTICE входят в колесо.
- Процесс проекта: SECURITY.md, CODE_OF_CONDUCT.md (Contributor Covenant 2.1), схема меток и их синхронизация,
  разделы заметок выпуска по меткам, выпуск по тегу (PyPI через trusted publishing и GitHub Release), Dependabot
  для действий CI, настройки ревью CodeRabbit.
- Логотип (штамп ОТК, SVG без зависимости от шрифтов), превью репозитория 1280×640, сайт документации на
  MkDocs Material (GitHub Pages; сборка `--strict` в CI ловит битые ссылки и якоря).
- Английская версия README (`README.en.md`) и основных страниц документации (`docs/en/`: команды, настройки,
  проверки, CI, пределы, неполадки); на сайте пока только русская.
- База не возвращена к виду до проверки (рабочая база, откат хука Platform Tools `pt post`) — код 2 с причиной
  `restore-failed`, а не «можно отправлять» или обычный дефект. Восстановители запросов запускаются без оболочки;
  извлечение редакции git работает и на Python 3.11.0–3.11.3. В «Известных пределах» — пароль ИБ в командной
  строке платформы и правка `[[queries.resolvers]]` как исполняемый код.
- Прогоны ОТК на одной копии ИБ идут по очереди: межпроцессная блокировка базы (файловой и `/S…`) на всё время
  загрузки, проб и записи состояния; второй прогон ждёт `environment.lockTimeout` (900 с), затем код 2 (`ib-busy`).
- Установка с нуля проверена на Windows и Linux: колесо в чистом окружении, `doctor`, `gate --static-only` на
  демо. Необязательная зависимость `otk-1c[com]` (pywin32 для внешнего соединения на Windows); без pywin32
  `doctor` говорит, что поставить, а не печатает ошибку импорта. Установка на Ubuntu без pip — `docs/linux.md`.
- Устройство пакета для разработчиков: подпакеты по слоям (`sources`, `probes`, `analyzers`, `gate`,
  `integrations`, `extras`) без импортов вверх, циклов и чужих приватных имён — проверяет тест; дополнительные
  инструменты (консоль ИБ, MCP, анализ ТЖ) отделены от проверки изменений. Команды и настройки не менялись.
  Совместимость с лабораторными версиями до 1.0 убрана: устаревшие ключи настроек, `[fullcheck]`, состояние
  сборки в прежних местах, поле `bsllsInfo` в `static.json` (сведения анализаторов — `analyzerInfo`).
  Типы на границах пакета проверяет mypy (CI и хук pre-push), ruff — сложность функций и правила
  безопасности; условия `#Если` разбираются без `eval`.
- Инструмент операций с копией ИБ — настройка `environment.ibTool` (`OTK_IB_TOOL`): пакетный Конфигуратор
  (`designer`, по умолчанию — на Windows быстрее) или `ibcmd`; результат в ИБ тот же. Полная загрузка выгрузки —
  `ibcmd` при любой настройке (втрое быстрее Конфигуратора), база на сервере — Конфигуратор. `ibcmd` в базе с
  пользователями без `environment.user` прерывается с подсказкой, а не ждёт тайм-аута; его сообщения об ошибках
  на Windows читаются (кодировка консоли).
- Работа без `ibcmd` (клиентская установка платформы, без компонентов сервера): полная загрузка — Конфигуратором
  с примечанием в сводке, безопасный режим с YAxUnit и расширения проб снимается внешним соединением (COM);
  `ibTool = "ibcmd"` без `ibcmd` — понятный сбой до начала проверки; `otk doctor` показывает, есть ли `ibcmd`.
- Выгрузка в корне репозитория находится сама, если `project.source` не задан, а в `src/cf` выгрузки нет;
  «модулей 0» при изменённых файлах выгрузки вне `--source` — с подсказкой про каталог. Файлы-указатели Git LFS
  без содержимого (объекты LFS не получены) — понятный сбой до загрузки в копию ИБ, а не «Ошибка формата потока»
  платформы; `git archive` редакции без объектов LFS — сбой с причиной и командой `git lfs fetch`. BSL LS
  находится и в хранилище расширения VS Code «Language 1C (BSL)».
- Статика: «Переменная не определена» — имя перед точкой, которого нет ни в модуле, ни в конфигурации, ни в справке
  платформы (несуществующий или переименованный общий модуль), как у Конфигуратора. Имена платформы, которых нет в
  справке, стандартные формы и методы менеджеров — словарь `platform-names.toml`; дополнить, не дожидаясь выпуска, —
  раздел `[platformNames]` настроек.
- Анализаторы BSL: какие правила дают ошибку, а какие предупреждение, — раздел `[analyzerSeverity]` настроек
  (`error` — добавить, `warning` — снять, отдельно для BSL LS и bsl-analyzer); ошибка в разделе — примечание в сводке.
- BSL LS на расширении: «метод общего модуля не существует» на заимствованном общем модуле больше не шумит — метод
  ищется и в основной конфигурации, как таблицы запросов.
- Для агентов: `gate --json` и `doctor --json` — итог одним объектом JSON в stdout (схемы `otk.gate-result.v1`,
  `otk.doctor-result.v1`), журнал — в stderr, коды выхода прежние. Причины «не проверено» и сбоев инфраструктуры —
  со стабильным `reasonCode` и `remediation` (что сделать): база занята, нет платформы, ibcmd, лицензии, YAxUnit,
  упал Конфигуратор, тайм-аут и др.; список — `docs/agents.md`. В `summary.json` — поле `infra`.
- Сбой самой ОТК (необработанное исключение) — код 2, а не 1 «найдены ошибки»; с `--json` — объект с
  `reasonCode` `internal`, `doctor --json` при битом `otk.toml` — объект с полем `error`. Неверный `report.open`
  сообщается до прогона, `static` и `run` без плана — «нет плана» одной строкой. `otk ci` больше не пишет `otk.local.toml` (и пароль) в checkout: переменные `OTK_*`
  накладываются на настройки в памяти. `collect --out -` печатает в stdout только план. `report --run-dir`
  принимает и каталог прогонов, как `gate`.
- Единый контракт перед 1.0 (`docs/contract.md`): что стабильно в 1.x, а что внутреннее. Поля JSON и ключи
  настроек — camelCase (`reasonCode`, `summaryPath`, `[designerCheck]`, `bslAnalyzerTimeout`), значения — kebab-case
  (`not-checked`, `ib-busy`), важность — `error`/`warning` и в `static.json`, и в `[analyzerSeverity]`; находка
  сводки — `rule` вместо `code`; проверка `bslls` — `analyzers`. Во всех файлах JSON — `schema` (`otk.<имя>.v1`) и
  `version`, внутренние (`static.json`, `run.json`, `designer.json`) — с `$comment`; план — `otk.plan.v1`
  (`plan.schema.json`). Схемы с абсолютным `$id` на сайте документации; публикуемые открыты для новых полей и кодов.
  Коды выхода всех команд: 1 — дефекты в проверяемом коде, 2 — окружение и сбой (`doctor`, `console`,
  `platform-help`, `controls --analyzers`). Переменные `OTK_*` сильнее `otk.toml` и `otk.local.toml` для всех
  ключей (что взято из них — `otk doctor`), неизвестные ключи настроек — предупреждение. Код причины задаёт место
  сбоя, а не текст; `infra` в `summary.json` — объекты `{reasonCode, message}`. `otk help` — справка ОТК,
  справка платформы — `otk platform-help`; `otk console --ib` вместо `--base`. Удалены синонимы: `--password`
  (пароль — `OTK_PASSWORD` или `otk.local.toml`), `[smoke] enabled`, `[hook] staticOnly`, `scaffold --worktree`.
  README на PyPI — с абсолютными ссылками, в метаданных пакета — ссылки на документацию и журнал изменений.
- Большая разница (все модули, `--base-dir`, крупное слияние): план собирается вдвое быстрее (УНФ, 15 тыс.
  модулей — 266 с вместо 569), статика модуля в 30 тыс. строк — секунды вместо минут; при находках больше 50 в консоль — краткая сводка (`--full` — вся); частые причины
  (одна ошибка в трёх местах и больше) — одной строкой в сводке. Каталог прогона и то, что в нём фрагменты кода, —
  в справке `--dir` и `docs/report.md`.
